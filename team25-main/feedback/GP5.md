## Code Quality

- Everything is organized and named pretty well. I understand generally what everything does just based off the names. Menu.py in particular is laid out very well. I can't really point to anything that needs to be refactored. Everything that is there looks good, it's just they don't have much.
- In their models.py file they have tables, classes, and queries separated by comments so that it is easy to tell what they are doing. Something they could refactor is to make a seperate models and views folders to make the code more readable.
- The team has not done the refactor that was proposed by the professors, but hopefully that will come when they work on their forms, actions, and charts. Besides this, the file structure is identical to profs and is therefore easy to navigate. I prefer going without the underscores in the naming for the classes, but otherwise function names, variable names, and class names read well. Their "about" route code is very concise, everything fits neatly onto one line of code without looking egregious. As encouraged by the professors for GP5, I would recommend breaking out forms, actions, and charts into their own files. There is a lot of commented out code from the profs repository, but I assume that will go away once their GP5 is complete.
- Their files are super easy to navigate, I also think their comments are really good and descriptive. The functions, variables, and classes seem to be named clearly and consistently. I would say to remove the commented out parts in some files, for example views.sql has a good amount of commented out code.
- They could implement new features. The css on the homepage is a good start, but I will need to see how the code progresses in order to fairly judge the project.
